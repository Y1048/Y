## 수정 목적

기존 양팔 코드는 오른팔에 축만 추가한 구현이 아니었다. 기존 오른팔의 손목 우선
처리와 접근 감속 등이 빠지면서, 손목 위치를 고정하고 회전만 시켜도 팔꿈치가
크게 움직이고 손목 위치가 벗어나는 회귀가 재현됐다. 충돌/범위 테스트 통과만으로
그 동작 품질이 보존됐다고 판단해서는 안 된다.

## 적용한 동작 보정

`MuJoCo_G1_Controller/scripts/g1_bimanual_motion_policy.py`의
`ArmMotionPolicy`를 좌우 공통으로 사용한다. 각 팔은 별도 선호 상태와 task를
갖지만, 두 팔의 해는 계속 **하나의 14축 QP**에서 함께 구한다.

| 기능 | 구현과 유지 조건 |
| --- | --- |
| 목표 접근 감속 | 관절 보정량과 가속도 여유로 접근 gain을 정한다. 손목 task와 posture task의 비율은 기존 오른팔 기준으로 유지한다. |
| 손목 우선 처리 | 위치가 맞고 회전이 필요하며 손목/충돌 여유가 있으면 어깨·팔꿈치 속도에 유한 비용을 준다. 관절을 강제로 고정하지 않는다. |
| 어깨 자세 보정 | 포착한 기준 자세 주변의 roll/yaw 선호와 yaw 접근 경계를 좌우 각각 적용한다. |
| 몸통 근처 목표 | 몸통 내부의 손목 위치 목표를 모델 경계 밖으로 보정하되 원래 회전 목표는 보존한다. |
| 팔꿈치 보조 | 필요한 상황에서 기준 자세에 고정된 보조 목표를 사용한다. 현재 높이를 계속 누적해 들어 올리지 않는다. |
| 위치·회전 우선순위 | 충돌/관절 제약과 오차에 따라 hysteresis를 적용한다. 회전 비용은 정상값의 0.5까지 완화하며, 도달 가능한 상황으로 돌아오면 복구한다. |
| QP 수치 처리 | 관절속도 단위로 축소하고 행/목적함수를 정규화한다. 관절 및 상대 충돌거리의 감속 여유를 추가한다. |

기존 `g1_upstream_mink_tracking.py`와 `g1_standard_mink_planner.py`는 수정하지
않았다. 자유 공간 비교용 기준으로 보존했다. 이 변경은 기존의 모든 오른팔
실행 경로를 통째로 교체하거나 동일하다고 선언하는 것이 아니다.

## 입력 필터와 진단 기록

기존 오른팔의 위치 60ms, 회전 50ms 시정수를 양팔 입력에도 적용했다.
이번 필터는 C#이 아니라 `g1_bimanual_unity_sim.py`의 `PairedHandFilter`에 있다.
수락한 새 packet의 sender 시간 간격으로 갱신하며, 긴 간격은 100ms로 제한한다.
이는 기존 C# 필터의 명목 전송주기 기반 갱신과 실행 위치/시간 기준이 다르다.

engage 순간에는 양손 필터와 neutral을 함께 초기화한다. 중복 packet은 필터를
진행시키지 않고, 한 손이 유효하지 않으면 양손 필터 모두 진행하지 않는다.
tracking validity, timeout, pinch, session/sequence 조건은 별도로 유지한다.
Quaternion은 허용된 직렬화 반올림을 정규화하고 최단 회전으로 보간한다.
원본 입력 packet은 기존대로 JSONL에 남는다.

새 JSONL 첫 행 `kind=run`은 `motion_policy=bimanual_motion_v1`, 엔진/패키지
정보, 네 Python 파일의 SHA-256과 시정수를 기록한다. 이 해시는 해당 파일 바이트
범위이며 모든 의존성/메시/설치 환경 전체의 해시라고 해석하지 않는다.
`kind=state`에는 내부 감속 이유·누적 횟수·남은 tail·팔별 보정 상태,
`control_tick_ms`, `loop_period_ms`를 추가했다. UDP feedback 계약과 Unity C#은
변경하지 않았다. 진단 항목을 추가한 곳은 JSONL이다.

## 보존한 제약

실제 geometry 검사 기준 5mm, QP 기준 6mm, 어깨/팔꿈치 90도/s,
손목 180도/s, 가속도 60도/s²와 관절 범위를 유지했다. 양팔 상호 충돌 쌍도
유지한다. `checked_stop_plan()`과 `clearance()` 함수 본문은 변경 전과 일치한다.
새 목표가 유효하지 않으면 이전에 검사한 감속 경로를 사용하고, 유효한 경로가
없으면 BLOCKED가 된다. 기존 joint-home 복귀 목적은 유지했다.
