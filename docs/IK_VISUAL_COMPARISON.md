# VR 없는 IK 시각 비교

루트의 `VIEW_IK_COMPARISON.bat`을 실행한다. Quest, Unity, G1 연결 없이 동작한다.
네트워크 소켓, DDS publisher, 로봇 명령은 만들지 않는다.

## 조작

처음에는 3D 8자 복합 동작으로 시작한다. F9 순서: 3D 8자 → 뻗으면서 회전 →
점검 스캔 → 손 위치 고정/다축 회전 → 기존 축별 진단 6종.
새 동작은 관절 명령이 아니라 손목 위치/자세 목표다. 각 관절은 두 IK가 계산한다.
몸통/도달 한계 때문에 목표가 제한될 수 있으며 모든 목표의 도달 가능성을 보장하지 않는다.
HUD의 travel은 시작부터 관절 이동량의 절댓값 합이다. arm은 어깨·팔꿈치 4축,
wrist는 손목 3축이며 오차/충돌 거리와 함께 비교한다. 작다고 무조건 좋은 해는 아니다.

BAT 시작 시 0.1~16배를 입력한다. Enter 기본값은 4배다.
각 동작의 20초를 원래 IK 설정으로 먼저 계산하며 진행률이 표시된다.
재생은 저장된 자세만 표시하므로 배속 변경이 IK 해에 영향을 주지 않는다.
처음 선택한 동작은 계산 대기가 있고 같은 동작 재선택/재시작에는 캐시를 사용한다.
끝에 도달하면 마지막 자세에서 멈춘다. F10으로 재시작한다.
headless 비교의 계산 프레임 수에는 배속을 적용하지 않는다.

- `F8`: 개선 계층형 planner / 기본 Mink 6D 단일 QP 표시 전환
- `F9`: 손목 X/Y/Z 회전, 위치, 복합, 몸통 방향 접근 순서로 전환
- `F10`: 두 계산을 같은 초기 자세로 재시작
- `F11`: 0.25 / 0.5 / 1 / 2 / 4 / 8배 순환
- `F12`: 일시정지/재개
- 창 닫기: 종료, `logs/ik_visual_comparison/latest.json`에 결과 저장

기존 1/2/N/R/Space는 비교 도구에서 처리하지 않는다. Esc는 MuJoCo 카메라 조작이며 종료가 아니다.
노트북 기능키 설정에 따라 Fn을 함께 눌러야 할 수 있다.
40/100 deg/s 뷰어 전용 제한과 8초 목표 주기 변경은 취소했다.
원래 프로젝트 속도 제한과 20초 목표 주기를 사용한다.
두 solver는 같은 시간의 손목 목표를 동시에 계산한다. F8 전환은 표시만 바꾸므로
같은 순간의 자세를 비교하려면 F12로 멈추고 F8을 누른다.
하늘색 구는 요청 손목 위치다. 화면의 pos/rot는 요청 손목 기준 오차,
gap은 계산된 충돌 거리다. 음수/거리 제한 미달은 안전한 결과가 아니다.
기본 QP의 속도가 검사를 통과하지 못하면 그 프레임은 적분하지 않고 이전 자세를 유지한다.
`REJECTED`와 누적 `rejected`에 표시되므로 창 종료와 구분할 수 있다.
reject가 있는 실행을 순수 QP의 성공 궤적으로 해석하지 않는다.

## 비교 범위

기본 Mink는 기존 프로젝트 vanilla 경로처럼 wrist_yaw 6D FrameTask +
PostureTask + DampingTask를 한 QP로 계산한다. 공식 G1 예제 전체를 그대로
복제한 것이 아니다. 모델/프로젝트 비용/동결 관절/속도 제한을 명시적으로 사용한다.
참고: https://github.com/kevinzakka/mink

개선 경로는 기존 FeasibleTargetPlanner.Plan을 사용한다. 요청 yaw 손목 위치를
현재 roll-yaw offset으로 보정해 center 목표를 만든다. 추가 planner 수락 판단도
포함되므로 순수하게 cost 하나만 다른 실험이 아니다.

기본 실행은 양쪽 모두 5/10mm 충돌 프로필이다. 20/40mm를 공통 적용하려면:

```powershell
py -3.11 backend/tools/view_ik_comparison.py --profile hardware-guarded
```

관절 상태를 직접 재생하는 기구학 비교다. PD/중력/실측 지연/외력 검증이나
물리 실행 허가가 아니다. 몸통 접근 목표는 도달 가능하다고 보장하지 않는다.
생성 XML은 임시 경로를 사용하며 실행용 공통 XML을 덮어쓰지 않는다.
